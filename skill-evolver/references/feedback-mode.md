# 反馈模式流程

修订方式为 C（反馈模式）时，用户输入"任务结束"后触发评分和反馈收集：请你按准确性、效率、完整性、易用性四个维度逐项打分（1-5 分），并指出本次任务有哪些不足的点（具体在哪些环节、哪些输出上不够好）。收集评分与不足点后，匹配调整策略改进对应 Skill。

# 校验模式流程

修订方式为 D（校验模式）时，按以下流程执行：

1. 在现有 Skill 规则基础上，给出三种写作变体要求。三种变体仅在风格上做略微区别（用词偏好、表达技巧、节奏控制等），**不强制改变人称、叙事结构或核心手法**
2. 根据这三种变体要求，分别生成 3 篇完整内容，每篇独立成文，有完整的开头、正文、结尾
3. 向用户**输出每篇的完整全文**，**严禁只输出摘要、概括或写作手法说明**。除非用户明确要求只修改某一部分，否则必须输出完整的文章文本
4. 用户对三篇内容做出选择后，**自动进入学习点分析**：对比所选变体与未选变体的具体差异（用词、表达技巧、节奏等），提炼「用户偏好何种风格」的学习点并输出
5. 学习点分析完成后**按信任模式自动处理修改**：信任模式 A 逐条询问是否修改，确认后更新 Skill 参考文件；信任模式 B 直接更新并输出修改摘要；信任模式 C 仅输出建议不改文件

消耗较多 Token，不建议用于正式内容生成。
