# 约束与注意事项

1. 不自动修改任何 Skill 文件（按信任模式执行）
2. 每次更新记录变更日志
3. 使用 `scripts\validate-skill.ps1` 去重检查
4. 仅修改 `skills/` 目录下的文件
5. 每次修改前备份原始文件到 `logs\backups\`
6. 不删除 Skill；未经用户指示不修改 skill-evolver 自身
7. 进化报告控制 Token 消耗不超过 2000

# 错误处理

| 场景 | 处理方式 |
|------|----------|
| 目标 Skill 不存在 | 报告错误，跳过 |
| 文件被占用 | 重试 3 次，间隔 2 秒 |
| 验证失败 | 回滚修改，记录错误 |
| 用户中途取消 | 停止当前操作，已执行不回滚 |
| 脚本执行失败 | 使用内置逻辑替代 |
| 状态文件损坏 | 重置为默认（禁用），记录警告 |
| 创建时目录已存在 | 提示选择覆盖或重命名 |
| 创建时用户退出 | 保存草案到临时文件 |
| 自动识别数据不足 | 提示进入指令创建模式 |

# 变更日志格式

每次更新记录到 `logs\evolution-log.md`，格式：日期、更新 Skill、原因、修改内容、影响范围、更新人。

# 帮助菜单

用户输入"帮助"时输出以下菜单，并在菜单末尾附上当前状态摘要（读取 `logs\state.json` 后报告 enabled、信任模式、修订方式、skill_states）。

```
═════════ Skill Evolver 指令菜单 ═════════

这个 Skill 负责观察其他 Skill 的使用情况，发现问题后改进它们。
菜单分五部分：怎么开关、怎么触发修订、怎么管理 Skill、怎么改配置、怎么建新 Skill。

─────────────────────────
一、开启与关闭

1. 「开始修订」
   同义说法：启用修订 / 开启技能进化 / 开始进化
   作用：打开技能进化功能。
   补充：功能已经开着时，输入它会直接显示当前配置；新对话第一次开启时，
   会先问你两个问题（改文件前要不要先问你、什么时候开始分析），答完即完成初始化。

2. 「结束修订」
   同义说法：停止修订 / 关闭修订 / 结束进化
   作用：在当前对话里关闭技能进化功能。
   补充：只关这一个对话，其他对话和新对话的默认设置都不受影响。

3. 「帮助」
   作用：显示这份菜单，末尾附当前配置状态。功能开没开都能用。

3a. 「状态」
   同义说法：查看状态
   作用：单独查看当前配置摘要（是否启用、信任模式、修订方式、各 Skill 开关），
   不触发任何分析。

3b. 「回滚上次修改」
   同义说法：撤销上次修改
   作用：把最近一次被修改的 Skill 文件恢复成修改前的样子（从备份目录读取）。
   说明：修改 Skill 前都会自动备份，所以随时可以反悔。

─────────────────────────
二、触发修订（什么时候开始分析改进）

4. 「任务完成」
   作用：告诉系统一个任务做完了。
   行为因修订方式而异：
   - 手动模式(A)：立刻分析这次任务，找出可改进点，生成报告；
   - 其他模式(B/C/D)：分析早已做过，此句只用来清空这个任务的记录，
     让下一个任务不被旧内容干扰。

5. 「修订完成」
   作用：手动模式(A)专用收尾指令。
   说明：分析报告出来、文件按你的意见改完之后，输入这句确认收工并清空任务记录。

6. 「进化技能」
   同义说法：优化skill / 技能复盘 / 更新skill
   作用：不等任何时机，立刻对所有启用中的 Skill 做一轮完整分析修订。

7. 「任务结束」
    作用：反馈模式(C)专用指令。
    说明：输入后系统请你给这次任务打分（准确性、效率、完整性、易用性，
    各 1-5 分），并指出本次任务有哪些不足的点，再根据评分与反馈决定怎么调整 Skill。

8. 自动检测（无需任何指令）
   生效条件：修订方式为自动模式(B)。
   说明：你每发一条命令、任务一做完，系统就自动检查一遍有没有需要改进的地方，
   并直接把结果说给你听。哪怕没发现问题，也会说一句「本次无学习点」，
   证明检查确实跑了，不会悄悄跳过。

─────────────────────────
三、管理哪些 Skill 会被修订

9. 「启用 <技能名>」/「禁用 <技能名>」
   例子：启用 human-writing
   作用：单独打开或关闭某一个 Skill 的修订开关。
   补充：被禁用的 Skill 只记录执行数据供体检用，不做分析修改。仅当前对话生效。

10. 「全部启用」/「全部禁用」
    作用：一次性打开或关闭所有 Skill 的修订开关。

11. 「检查技能库」
    作用：给所有 Skill 做全面体检（包括已禁用的）。
    检查项：文件结构、内容质量、引用完整性、格式、重复度，最后给健康评分。

─────────────────────────
四、修改配置

12. 「修改配置」
    作用：重新设置当前对话的两个选项：信任模式（改文件前要不要先问你）
    和修订方式（什么时候开始分析）。详见下方模式说明。

13. 「修改新对话默认」
    作用：修改以后每个新对话的默认配置，写入 config.json 长期生效。
    可改项：新对话是否自动开启本功能、默认信任/修订模式、各 Skill 默认是否启用修订。

─────────────────────────
五、创建新 Skill

14. 「创建 Skill」
    同义说法：新建 Skill / 添加技能
    作用：按流程新建 Skill（描述架构 → 补充细节 → 确认组成 → 生成文件）。
    补充：同一个操作模式重复出现 3 次以上，系统会主动提议把它做成新 Skill。

─────────────────────────
两种模式的区别

【信任模式】回答的问题是：改文件之前，要不要先经过你同意？
    A. 询问后修订（默认）  先列出全部想改的地方，你逐条点头，才动手改
    B. 直接修订            不询问，直接改文件，改完汇报改了什么
    C. 禁止修订            只做分析和建议，一个文件都不碰

【修订方式】回答的问题是：什么时候开始分析改进？
    A. 手动模式  你说「任务完成」才开始分析，改完说「修订完成」收尾
    B. 自动模式  每条命令做完立刻自动分析并报告；「任务完成」只剩清空记录的作用
    C. 反馈模式  你说「任务结束」后，按四个维度打分（1-5 分）并指出具体不足的点，再根据评分与反馈调整 Skill
    D. 校验模式  在现有 Skill 基础上给出三种风格变体（用词、表达技巧的细微区别），
                 分别生成 3 篇完整稿件供你比较；你选定一篇后，自动分析学习点
                 并按信任模式处理修改（询问确认或直接改）。
                 最费 Token，正式产稿不建议用

─────────────────────────
工作原理备忘

- 分析对象   只有开关打开的 Skill 会被分析修改，关掉的只留记录备查
- 修订流程   记录执行情况 → 找出可改进点 → 分类整理 → 出报告 →
             按信任模式处理 → 动手改文件（改之前先备份）→ 验证；
             改坏了自动恢复原样
- 关注点     新捷径 / 失败模式 / 反模式 / 工作流改进 / Token 节省 / 内容过时或错误 / 修改路径追踪
- 安全机制   每次修改前备份到 logs\backups\（未备份不得修改）；每次更新写入变更日志
             （写入前查重）；报告学习点合并后不超过 5 条；报告 Token 消耗控制在 2000 以内
- 回滚       说「回滚上次修改」可从备份恢复最近一次修改的文件
- 执行记录   每次任务完成后追加写入 logs\execution-log.md，清空上下文后仍可追溯历史
- 配置存储   当前对话的设置在 state.json（对话结束即失效）；
             长期默认设置在 config.json（所有新对话沿用）
```
